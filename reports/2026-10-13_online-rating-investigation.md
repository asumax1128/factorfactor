# オンライン：難易度別レーティングの調査結果

オンライン本番仕様の変更・本番Firebase変更・既存レート移行は実施していない。数学の塔の公開コミットは`9fa9ac3`。設計とエミュレータ監査だけを別の`design/online-difficulty-ratings`ブランチへ保存する。

詳細な[実装・移行・認可案](../docs/online-difficulty-rating-plan.md)を承認用の仕様として参照。

| 調査項目 | 結論 |
| --- | --- |
| 現行レート | accounts/$key/statsのrating・season等。全難易度共通、A/B別勝敗はあるが難易度別レートではない。 |
| マッチング | qm/slotが1枠。成立後のA-easy等の投票で難易度まで決める。 |
| 履歴 | recordMatchはdiff/matchIdを保存しない。部屋結果は次戦に削除する。集計値だけでは正確な過去の再計算不可。 |
| 認可 | 本人はstatsの任意レートを書ける。子階層でwrite:falseを追加しても親許可を取り消せない。 |
| 結果 | 参加者が初回resultを作り、ホストは親許可で結果を上書きできる。新レートの根拠にはそのまま使えない。 |
| 重複 | recorded.currentは画面内のガード。recordMatchは同じ試合を2回加算でき、永続台帳がない。 |
| ランキング | 現在は総対戦3戦以上・レート/勝率順で上位10件。新ランキングは難易度ごとの確定記録を使う。 |
| 称号 | 既存ゴールド1580、マスター1820等は保持。追加は5個の案。 |

## 推奨案とユーザーへの影響

- 旧レートを削除せず、移行時点の「旧総合レーティング」と旧称号を保存。新EASY/NORMALはそれぞれ1500から開始する。旧の高レートを片方へ推測配分せず、両方へコピーもしない。
- new ratingsをstatsの中ではなく`onlineRatedV2`という保護された兄弟枝へ置く。サーバーが問題・結果・難易度・UID/accountKeyを検証し、Eloと両者の加減算を一意台帳付きtransactionで確定する。
- 難易度・プロトコル別の新キューと新試合を旧qm/roomsから分離。マッチ後はA/B投票だけ。部屋対戦・大会・レイドは既存経路のまま。
- 新ランキングはEASY/NORMALタブ。自己成績は両方表示し、未対戦1500は順位一覧には掲載しない。掲載は各難易度3戦以上の案。
- 称号の提案：EASY/NORMALの達人各1730、EASY/NORMALマスター各1820、両方1820の「双璧のマスター」。新方式の生涯最高値で独立判定し、既存称号は削除・改名しない。
- 新レートの対象を人間2人のランダム対戦A/Bに限り、CPU/ゴースト代役・ゲスト・部屋対戦・大会は対象外にする案。この範囲は未承認で、既存CPU等のゲームを削除する案ではない。

## 実行済み

`tests/online-rating-audit.cjs`：既存recordMatchをそのまま抽出して2回呼び、2戦・レート+32の重複を確認。実Firebaseエミュレータで本人/他人、任意レート、未検証結果作成、ホスト上書き、子階層の拒否が親許可を覆せないこと、独立枝へのクライアント書込拒否を確認。

実行コマンドはエミュレータ内で`node scripts/run-math-tower-rules.cjs rating-audit`。Console提供ルールの場所を`RTDB_RULES_BASELINE_FILE`で指定する。demoプロジェクト・127.0.0.1:9000固定で、本番データを操作しない。テスト内で追加した拒否ルールもエミュレータだけの一時データ。

既存のオンライン2人対戦、大会、クラスレイド、ログイン・成績保持・ランキング、226共有関数のAST比較も通過。オンライン実装は数学の塔修正の前後で同じ。

## 未実施と承認事項

本番データ全件・残存履歴・最新配信ルール・料金プランの直接取得は、管理接続がないため未実施。提供ルールとコードから確認した構造を、本番データの棚卸し完了とは扱わない。秘密鍵/PINをチャットに送る必要はなく、管理者による最新ルール共有、匿名化した構造/件数/履歴有無の確認で補う。

新マッチング・新レート・新ランキング・新称号はまだ製品に実装していない。必須の新仕様テストは詳細案に記載し、承認後にサーバー/クライアント両方で実施する。iPhone Safari実機も未検証。
