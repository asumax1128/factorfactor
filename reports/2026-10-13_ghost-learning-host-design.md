# ゴースト・学びの部屋・限定開催権限：調査と設計

2026-10-13。正式mainの7d30c3eを調査。以下6項目は**未実装、確認待ち**。本番データを直接取得していないため、残存件数や全プレイヤーの履歴の有無は断定しない。記載は現行コードの保存方式・取得処理による。

## 1. ゴースト対戦履歴

[index.htmlのGhostNews](../index.html) は `ghostlog/$owner/$id = {by,o,mode,diff,at}` を読む。これは「本人のゴーストが他の人に挑まれた」通知で、本人がゴーストへ挑んだ詳細履歴ではない。BattleGameがゴーストから見た結果を相手側へpushする。`o=w/l/d`、byは挑戦者の表示名で、UID/accountKeyや各問の詳細はない。

通知確認時、GhostNewsは `accounts/$key/stats/ghostW,ghostL,ghostD,ghostSeen` をtransaction更新し、ゴースト勝利1回につきGHOST_WIN_EXP=5を付与する。2週間より古い通知の削除処理がある。PlayerProfileに既に「ゴーストの戦績」の勝敗集計はあるが、日時一覧や自分が挑んだゴーストの名前履歴はない。集計表示は公式stats.games>0のブロック内にあるため、ゴーストだけの活動では表示されない場合がある。記録が残っている範囲だけ表示可能。既存vsはゴースト相手のacctが空なので完全なゴースト履歴として復元できない。

提案：自分の挑戦履歴と自分の分身の活躍を分ける。新しい `ghostV1/users/$account/events/$matchId` に本人から見た勝敗、対戦相手key/表示名、mode/diff、日時、EXP、必要なら問題集約を保存。本人のUID/account対応をルールで検証し、試合IDで二重確定を防ぐ。過去の欠落履歴を捏造しない。新しい保存枝には事前ルール差分が必要。既存GhostNewsでは集計transactionとaddExpが別処理で、他端末で確認済みでもXP付与側が再実行される余地がある。新設計では結果とXP受取を試合IDで一度だけ確定し、このリスクを引き継がない。

## 2. 学びの部屋の最高速

`applyLearn` は `prof.lv/L1..L9` にn（試行数）、ok、ms（正解時の合計ミリ秒）を蓄積。`LearnApp` は正答率ok/nと平均ms/okを表示。レベル別のmin値は保存していないため、合計から過去の最短値は復元できない。`stats.bestMs` はBattleGameのA/B最速だがレベル別ではない。

提案：prof.lv/Lxへ `bestMs` を追加し、有限・正の正解時間だけmin更新。未記録は「−」。誤答・時間切れ・未完了の問題、ドリル/デイリーのlate（ミスの後の正解）は除外する案。計測上限は各モードの既存タイムアウトを使う（共通QUESTION_TIMEOUT_MS=20000、塔は別）。異常に短い値の下限は監修・実機測定後に承認を得る。値を都合よく補完しない。

正解時間はcreateBEngineなら `Date.now()-s.qStart`、Aならclaim.at−qStartA、PracticeRunnerならDate.now−qs。各モードの計測原点は完全には同一でなく、平均を改変せず同じ計測を利用する。migrateGuestExtraのmin移行も合計ではなくminで統合する必要がある。登録アカウントのprofは既存の本人書込ルール内で追加可能だが、実装は確認後。

## 3. 生徒の限定開催権限

TeacherAreaは `teachers/$key` の登録で大会・授業レイド・TeacherDashをまとめて表示。unlockTeacherはteacherKeysを確認後、teachersに{name,at}を書く。rooms/$code/metaの現行validateも大会/レイドでは教師登録とloginsの対応を要求。数学の塔のaccess grantは別機能で、開催権限へ流用しない。

提案：`eventHosts/$student` にissuer（付与した先生）、enabled、tournament/raidのboolean、付与日時を保存。学生本人の読取と、先生本人のアカウント連携・教師登録を確認した付与/取消だけ許可。生徒は自己付与できない。issuerを任意に差し替えて権限を奪えないよう、不変条件・取消者の範囲を定める。

UIは専用の「開催係」欄で2ボタンだけ表示。teacherKeys、teachers、先生PIN、TeacherDash、塔の先生grantへは一切権限を渡さない。metaの大会/レイド検証に種別ごとの有効grantを追加し、host/account/issuerを一致させる。権限取消やissuer教師取消後の新規開催とホスト管理操作は拒否する。進行中の参加者の回答は不要に止めず、先生が引き取るか終了する導線を設計する。既存ホストのstate書込権限だけでは取消後の継続管理を止められないため、state等の関連枝の差分も必要。変更前に全文差分と認可テストを提示する。

確認事項：付与した先生だけが取消するか、他の先生も取消できるか／取消時の開催中イベントを先生へ引き継ぐか。

## 4. 賞金首からのゴースト対戦

BattleHomeは既存stats.streakで一覧を作る。`bountyOf`: 3連勝から10、1連勝追加ごと+10、上限100。現在は名前からPlayerProfileを開くだけで、ゴースト開始・本人限定の7日非表示はない。

提案：privateな `ghostV1/users/$owner/bountyCooldowns/$target` に勝利日時と非表示期限を保存。自分の一覧だけ期限内の対象を除外、敗北では更新せず、7日後に再表示。同じアカウントの端末で共有する。本人のghost履歴とXPの一度だけの確定を同一試合IDで扱い、通信再送・端末切替の二重取得を検証する。accountsは祖先.readで認証ユーザー全員に読取許可があるため、本人限定履歴をその下へ置くだけでは非公開にできない。

XP提案：勝利8 EXPを基本にする（既存CPU勝利8と同値）。賞金ボーナスを付ける場合は既存bountyOfの範囲内・1対象7日1回とする。これは承認前の提案で、数値を実装していない。敗北時のEXP、7日間の対象を難易度共通にするか、日時はServerValue.TIMESTAMP基準でどう確定するかも確認する。Sparkでクライアントの勝敗自己申告を完全には検証できず、公式レートと独立させる。

## 5. みんなの成績からのゴースト対戦

既存PlayerProfileに対象keyを渡せる。詳細へ「ゴースト対戦」を追加する案。対象prof.lvに20問以上の記録がある場合だけ利用可能とし、足りなければ不可と表示。特定相手を選ぶので、pickGhostのランク帯のランダム選抜は使わない。本人の過去分身は別表示で混同しない。

新しいゴースト練習は本編オンラインと独立した非レート対戦として構築する。旧startBotは通常対戦結果をrecordMatchへ渡し旧stats.ratingも更新し得るため、そのまま流用は禁止。表示名・学習プロファイルからCPUを作る部分だけ再利用し、新制度EASY/NORMAL、旧レート、公式オンライン勝敗を変えず、XP/専用履歴だけ保存する。

## 6. ゴーストの強さ：現行コードの計算式

対象：`index.html` のghostProf、ghostConf、cpuThink、cpuMiss、pickGhost、CpuBots、BattleApp.startBot/startMatch。新Sparkのすぐ遊ぶにはゴースト代役がなく、以下は旧qmの代役処理とCPUの仕組み。

| 項目 | 実装 |
|---|---|
| 通常CPU基準 | CPU_LEVELS.normal: `t(lv)=4+0.9*lv` 秒、miss=0.12 |
| 記録の速度 | 正解が2問以上あるレベルは `clamp((L.ms/L.ok)/1000,1,18)` 秒。小数2桁に丸める |
| 未記録レベルの速度 | 記録のあるレベルで `記録速度/通常CPU速度` の比を平均し、通常CPUのそのレベル速度へ掛ける。全くなければ比1 |
| ミス率 | 試行3問以上なら `clamp(1-L.ok/L.n,0.02,0.45)`。不足レベルは取得できたミス率の平均。全くなければ0.12 |
| 毎問の速度の揺らぎ | `cpuThink=conf.t(level)*(0.6+Math.random()*0.8)*1000` ms。平均の60〜140% |
| 正誤 | B: `Math.random()>=cpuMiss` なら正解。A:ミス確率でお手つきし、再考はロック後にcpuThink×0.4 |
| 必殺技を使う試合 | `sp=round(spGames/bGames,2)`、記録なし0.8。試合開始時にMath.random()<spで使用有無を決める |
| 必殺技の選択 | ゲージ満タンで600〜2100ms後。HP<40なら回復、保留攻撃があれば盾、それ以外は大攻撃 |
| 対象選び | 自分以外・prof.lv合計20問以上・同じランク帯または1つ上。候補からランダム1人 |
| 旧待機の代役 | QM_BOT_MS=18〜24秒。定数は格上10%、同格30%、残り通常CPU。古いコメントの「20%」は現行定数と不一致 |

本人の過去記録は使うが、個々の回答・実際の誤答選択・問題の得手不得手を時系列で再生しているのではない。個性はレベル別平均速度・ミス率・必殺技率。速度は最速ではなく正解の平均。レベル別profは難易度混合なので、同じLvではEASY/NORMALで別の個性にならない。問題・枚数・試合長は選択難易度の既存エンジンに従う。DIFFICULTY_CONFIGはEASY15問/6枚、NORMAL30問/9枚。旧qmではdiff未指定ならeasy。makeBank.level(n)は既存レベル進行を使う。

未記録レベルの推定速度には1〜18秒の再clampがなく、タイムアウトとの兼ね合いに注意。正答率100%でも2%のミス、低正答率でも最大45%のミスに丸めるため、本人の完全なコピーではない。必殺技率や集約msの異常値の検証は十分でない。採用候補がなければ通常CPU、取得失敗もnull扱い。

ソロは `fxf_solo_ghost_v1_$account` の難易度別ベストscore/splitsを端末へ保存。デイリーはdailyの日別splitsをGhostLaneで比較する。これらの分割タイム再生とオンライン代役CPUは別機能。

改善案（未実装）：最低サンプル数の明示、難易度別プロファイル、十分な記録時だけ本人寄りにする、推定値/異常値の範囲統一、選択式の非レートゴースト練習、速度コピーの精度を画面で説明する。まず上記のXP・履歴・開催権限の確認を受けてから実装する。
