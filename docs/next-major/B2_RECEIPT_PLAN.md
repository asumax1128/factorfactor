# B2 安全離脱後の結果受領 実装計画・テスト項目（Ver.6.3 候補・ディレクター承認済み設計）

作業ブランチ: `claude/v62-b2-host-disconnect` のみ。main・dev・公開CI・本番Firebase（データ・ルール）には触れない。追加する保存項目はすべて任意（既存データの初期化・削除なし）。

## 段階（各段階で全テストが通ってから次へ。失敗したら止めて報告）
1. 保存ACKとミッション（`recordMatch`/`flushOnlineLearn`/`missionEvent`、受領画面）
   - 完了判定は「サーバー確定を待つ確認トランザクション」3本（stats / prof / mis）の確定スナップショットだけ。`B2_RCPT.ack` やローカルの `get()` は証拠にしない。中止型トランザクション（`undefined`）は使わない。
   - ミッションの進捗と冪等印 `mis.s[試合ID]` は同一トランザクション。学習記録の印とは独立（常に実行）。試合日が今日でない／時刻不明は加算しない（確認は対象外＝完了扱い）。
2. シーズン境界: 試合のシーズン = `game.time` のJST月。旧シーズンはレート・seasonMax・maxRating・seasonHist に触れず、他は反映。時刻不明は時刻依存の処理をすべて保留。
3. 旧連勝 `stats.sl`（32件）: n0・bt・台帳から時刻順に再計算。移行は現在の streak を n0 に。載せられない受領は勝ち=加算せず、負け=n0を0にする安全側。maxStreak は下げない（最新のときだけ更新）。
4. リベンジ `vs[相手].vl`（6件）: 隣接2件だけの増分更新。旧データの `last` は基準（bt 以降のみ使用）。
5. 日別連続 `dl`（60日 + pre）: dayStreak は再計算、maxDayStreak は既存最高を保持。Spark の日別更新も共通関数に統一。

## 必須テスト（実SDK + Firebase Emulator。モックのみでの完了は不可）
- 段階1: 未ACKのローカル変更がget()から読める／確認が確定まで保留／ACK前のブラウザ終了／戦績成功・学習失敗・ミッション失敗からの再試行（完了済みを二重加算しない）／独立した2つのSDKクライアントの同時受領／ミッション進捗と印が同時に確定／別端末・ACK未保存での再受領。
- 段階2: 前月末の試合を翌月に受領（レート・履歴不変、戦績・EXPは反映）／時刻不明。
- 段階3: 任意の順序どおり列で旧方式と一致（性質テスト）／受領順の入れ替え／32件境界（n0・bt・現在連勝・最高連勝）／移行の瞬間に値が不変。
- 段階4: 全順列（n≤6）で結果一致／6件超／旧データ移行（baseline）。
- 段階5: 前日分の遅延受領と補完／Sparkの参加日を含む／dayStreak と maxDayStreak の区別／60日超の連続（pre）。
- 全体: 既存の回帰一式（legacy-regression・各ブラウザ・単体・Emulator検査）。
