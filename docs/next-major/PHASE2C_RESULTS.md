# Phase 2C：確定結果の可視化（第1コミット）

基準 `bdb51b4`、開発ブランチ限定。Phase全体の完了ではない。

## 実装

- `server/online-rated/b2.cjs`：開始時の0点と正解ごとの確定時刻・連番・加算点・全参加者の累積得点を`game.scoreTrace`に保存。同じ既存トランザクションに含め、追加購読／追加書込み命令はない。勝敗／HP／得点式／履歴／レート／報酬処理は維持。
- `src/b-result.cjs`：一つの最終スナップショットを検証。連番欠損・不一致重複・終了後イベント・最終得点不一致・旧試合の履歴欠損はグラフ不可。同一イベントの一致重複は除去。UIで得点式を再計算しない。
- `src/online-spark-client.cjs`：既存結果responseに`bResult`を追加。両者は同じ確定得点連番まで描画。
- `src/next-results-ui.jsx`／`ui-next/results.css`：階段状の時間軸グラフ、色と線種、凡例、得点差、イベント選択、逆転点、合計指標、加算履歴。レーティング対戦／ゴーストと4桁ルームの両結果へ接続。履歴がなければ説明だけ表示。
- A結果は既存の詳細・判定・推移を保持して配色を調整。欠損補完や勝敗変更はない。
- C結果は既存liveの保存済み正解数・得点・最終報告コンボを個人／チーム別に表示。時系列はなく、攻撃／相殺／防御／回復／個人HP寄与は未記録と明示。総合貢献スコアを新設しない。既存C liveは全員一括の確定スナップショットではないため、「終了画面で取得できた保存済み報告」と表示し、同期済み詳細履歴と誤認させない。
- ビルド／公開ファイルのステージ対象へ新JSを追加。ただし今回公開は行わない。

## 互換性・負荷

新規試合だけ完全なtraceを開始。途中の旧試合から履歴を捏造しない。試合ごとの既存保存オブジェクトの拡張で、ユーザー構造・本番ルールは不変。イベントは正解1回につき1行で、参加者全員の得点を含むためペイロードは増える。最大180秒・次問待機420msの既存制約下で上限は有限。新規全件読込・常時監視・独立したイベント書込はない。
