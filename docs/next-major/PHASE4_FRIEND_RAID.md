# 第4次：フレンドレイド開催条件・4難易度

本番へのルール公開・旧プレイヤーの戦績変更なし。新しい接続はloopback＋demo Emulatorだけで有効。通常の既存フレンド／クラスレイドは互換経路を保持する。

## 確定対人戦10件

`src/friend-raid-next.cjs`は本人の既存profile.processedから候補IDを最大30件だけ確認し、5件ずつ読み、10件確認できたら止める。対象はonlineSparkV1/matchesのsettled、異なる人間アカウント2名、A/B・イージー/ノーマル、game結果とreceiptの勝者一致、本人の参加が確認できる記録のみ。CPU、自己ゴースト、通常ゴースト／BOTの補完、未確定試合は除外。旧stats.games、stats.B、E/Nの合計値をもう一度加算しない。

判定不能は旧対人戦数を推測せず理由を表示。古い試合が残っていない場合や、最大30候補内に必要数がない場合の救済・追加調査は承認待ち。現行profileの人間戦gamesは初期移行で0から開始し、ghostは別bucketで増えるが、その合計値だけを新しい証明書の発行根拠にはしない。

10件のIDとサーバー時刻を`friendRaidNextV1/eligibility/<account>`へ不変の証明書として保存する。以後は証明書1件の読取のみで再利用する。毎画面の全件取得や常時監視は追加しない。旧勝敗・レート・EXPは更新しない。

## 候補ルール

`scripts/next-friend-rules.cjs`は既存v525ルールを**メモリ内で合成**するEmulator用builder。既存認可をANDで保ち、以下を追加する。

- 本人のログイン権限と実際の異なる確定対人戦10IDをルール側でも検証する。旧statsの数値だけや、別人のIDでは証明書を作れない。
- 証明書の削除・日時やIDの差し替えを拒否。
- 新規フレンドルームのmetaには本人の証明書が必要。他人の適格アカウント名を借りた開催も拒否。
- 既存のフレンドmetaは同じアカウント・同じcreatedAtのままなら互換保持。クラスレイド・大会の既存教師認可はそのまま。
- 新friendPolicyVersion:1ではfriendPowerとpowerが一致し、承認済みeasy/normal/hardだけを許可。鬼や矛盾する共有設定を拒否。

builderはアップロードや本番ルールファイルの上書きを行わない。本番公開には別承認が必要。

## 難易度

専用定義をクラスのRAID_POWERから分離する。既存3段階の倍率0.7／1／1.4を変えず、表示はよわい／ふつう／つよい。4つ目の鬼は倍率null・disabled・調整中。未承認の仮数値は作らない。新設定はルーム→戦闘→再挑戦へ保持。直接設定を渡しても未承認値では開始しない。
