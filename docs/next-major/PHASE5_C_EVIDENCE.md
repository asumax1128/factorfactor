# C方式の確定貢献：集計境界と残るwriter

`src/c-contribution-next.cjs`は**確定authorityログを読む純粋な集計器**。既存Cエンジン、勝敗、HP、通信処理へはまだ接続していない。現時点でC貢献記録が実戦で完成したという意味ではない。

## 実装済み

専用連続revision／終了revision／試合ID／actor／確定時刻を照合。同一revisionの同内容再送は一度、矛盾・欠損・終了後イベント・同一効果の別revision再記録は拒否する。全員同じ終了revisionまでの記録から個人別の独立指標と時系列を出す。

|指標|必要な証拠|含めないもの|
|---|---|---|
|攻撃ダメージ・カード|受信者による着弾確定、送信者・対象・eventID|送信試行／保存ACKだけ／相殺済み部分|
|相殺量|受信攻撃eventIDに対する本人の適用確定|旧cancelTotalの合計を攻撃回数に変換|
|防御回数|blocked確定eventID、対象本人|防御ダメージ量を回数に換算|
|カバー量|同チーム受信者のcovered確定、送信者照合|味方への送信試行量|
|個人回復HP|独立した本人回復operationの確定before/after|自然減少／被弾等が混ざった共有HPflush|

単一総合ポイントは作らない。共有HPの増減を個人へ按分しない。ユニットで再送・各指標・欠損・矛盾・試行量排除・共有HP排除を確認。

## 未完成：確定イベントの発生源

現在の`createBEngine`は攻撃setの失敗をcatchしてもsentを加算し、仲間カバーは要求を送った時点でcoversを加算する。受信者の相殺・防御・着弾は揮発状態で、共有HPにはdqの合算transactionを送る。現行保存値だけでは上表のすべてを復元できない。

次は**Emulator限定**で、受信eventID・適用operation・前後revision・終了バリアを同じ冪等トランザクションへ保存するwriterを追加する必要がある。`committed:true`という自己申告だけを信頼してはならず、ルールまたは信頼されるauthority側の操作結果に結び付けること。集計器はその認可や正当性を代替しない。確定writerがないまま現在のC結果へ推測グラフを追加しない。
