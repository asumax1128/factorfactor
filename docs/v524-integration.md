# Ver.5.24 実装・運用引き継ぎ

## 公開前提

基準は5.23（4b1574b）。5.24の公開はmainの検証成功後に行う。`release/v524`のActionsは検証のみで、Pages公開はmainの検証成功後に限定する。

Firebase管理認証はこの環境にない。`firebase/v524.candidate.rules.json`は以前の所有者公開候補`ghost-host.candidate.rules.json`へ必要な差分を追加したもの。所有者は候補debd263の全文をConsoleで公開し、2026-10-14に「完了」と回答した。認可・差分テストはEmulatorで通過済み。今後のルール変更時も、その時点の現行全文とバックアップを確認する。データのインポートや料金プラン変更は不要。

## ハイパーゴースト

`src/hyper-select.cjs`が既存`core.rankings`と同じ季節補正・掲載条件・同順位の定義を使い、画面と同じ先頭10件へ限定する。ノーマルの人間3戦などの掲載条件も維持する。学習20問以上を抽選対象とし、重みは11−順位。旧実装はhyperでランク差のoffsetが未指定となり、全候補を対象にしていた。

自己候補も許可するが、既存の自己練習ガードでレート・勝敗・EXP・称号・学習・受信通知を書かない。ハイパー0候補はエラー表示し、検索の補完予約を解除する。

## デイリー

所有者の追加指定により15／30／50問。`server/daily-play.cjs`は既存ソロの生成関数、タイム判定、レベル得点、ハード後半の展開問題を抽出して再利用する。日替わり共通seedは廃止し、各挑戦の乱数seedを保持する。指定された完走条件のため、誤答もその問を終えたものとして進む。ソロ本体のクリア条件は変更しない。

`games/factor/dailyV2/attempts/<account>/<JST epoch>/slots/0..2`の予約確定で消費する。日付キーは`floor((serverTime+9h)/24h)`。ルールでも同じserver `now`から確認し、端末日付・任意キーによる上限回避を拒否する。同一SDKの予約は直列化し、別端末間はRTDBトランザクションで競合処理する。ACK不明の再送は同じidを復元する。開始済み挑戦の再読み込み・退出に返還はない。

完走時刻は最後の回答時点、経過時間は単調増加時計を使用し、結果送信待ちは含めない。開始日の部門に記録する。正当な日跨ぎ完走を許すため、翌日0時から20分の終了猶予後に優勝結果を固定する（最大50問×20秒＋遷移を含む）。途中終了も得点を保存する。

部門別recordsは得点→クリア→時間／正解数→確定時刻のsortKeyを持つ。TOP10だけをqueryする。自身の不変な挑戦結果を根拠にbestを更新し、同時にleaderを更新する。ルールはleaderが実在の最良recordであることを維持するため、recordとleaderを同時検証する。全件読み取りや深夜の全ユーザー更新は不要。

finalsは猶予後のleaderの完全なコピーを一度だけ許可する。本人が参加した未処理日をログイン時に確認し、本人の優勝proofに限ってdailyV2/titlesへ永続付与する。3部門を保持するとdaily_kingを追加する。旧称号のIDや装備キーは維持し、日次称号の装備に保護されたproofを要求する。

ソロのローカルTOP3と既存Google Apps Scriptへ同じ得点・正解数・難易度を送る。GAS側のソース・管理権限はこの環境にないため、ネットワークのACK喪失まで含む外部サービスのexactly-onceは保証できない。共有receiptで自動の重複送信を避ける。既存GASのランキング・総得点集計をそのまま利用し、既存記録は消さない。

デイリーの完走EXPは既存の初回20／追加5を日別receiptで一度だけ加える。通常ミッションの導線を保持する。ソロ本体のEXP・レートは変更しない。

## B2

`server/online-rated/b2.cjs`はrules=b2の新規試合だけに使う。旧B・CPU・Cおよび開始済み試合は従来エンジンを維持。ルーム2〜4人の脱落・攻撃対象を保持する。クラス大会の旧進行は変更しない。

試合・HP・20秒期限・KOを共有時刻で進める。自然KO→試合終了→各タイマーという同一処理順を使い、同じ確定処理で両者KOなら引き分け。試合終了時の得点判定は期限までの確定得点のみを使用する。

偽カードは既存因数と掛けて別解にならないか検証し、表示に識別用スタイルを付けない。着弾／応援除去は次の盤面で反映。ボーナス枚数は現在の問題に置いた枚数を固定して使う。コンボ10秒は操作可能時から、3秒カウンターは最初の到着から。FREEZE中は両タイマーだけを止める。

ゲージは2コンボ目以降level×3%、100で自動発動。相手が凍結中は100のまま保持し、解除後に別の3秒を開始する。自動発動は入力操作とは分離する。問題・カードは凍結中もDOMへ描画せず、不透明な氷と残秒を表示する。

対人戦の回答intentはRTDBのServerValue.TIMESTAMPで不変記録し、`src/b2-pump.cjs`で順序・seq・問題IDを検証して再生する。正誤のローカル表示と公式得点は分離する。試合中だけの単一監視で全体getの反復を減らす。通常は先頭参加者がheartbeatを進め、停止時は他方が引き継ぐ。ルームは既存ホスト権限で共有処理する。ゴーストは既存のローカル処理・まとめたcheckpointを維持する。

観戦応援は登録accountで共有する3つのintent枠。複数タブ／UIDでも同じaccountの枠を再利用し、対戦参加accountによる応援を拒否する。10pt×3回、30保持、次問の除去は最大3枚。未登録ゲストは観戦のみ。

RTDBルールは認可・時刻・順序proofを検証するが、Sparkのルール内でJavaScriptの全戦闘エンジンを実行するものではない。既存のクライアント／ルームホスト方式を前提とし、管理サーバーによる全面的な不正プレイ検出を追加したとは主張しない。

## 維持・検証

5.23の開始前DOM遮蔽、A確定得点グラフ、自己練習の報酬禁止、歴代MASTERエフェクト、現在／最高レートと整数表示を維持する。因数カードの通常入力はドラッグのみ。数式フォント・塔のゲームロジックは変更せず、表示の難易度名だけカタカナへ統一する。

`npm run test:online-v524`、`tests/v524-emulator.cjs`、既存全回帰を実行する。Native SDKテストはdemoのAuth/RTDBのみで、本番のユーザーデータへ接続しない。iPhone／Chromebook実機は未確認、Chromiumのタッチ・スマートフォン縦画面とPCで検証する。

Spark・既存データを維持。常時全プロフィール監視、Cloud Functions、Blaze、全員の一括書換えは追加しない。JSON計測はアプリのpayloadの目安で、Firebase課金通信量そのものとは区別する。

## 実績・称号・きせかえ監査

`reports/titles_achievements_cosmetics_audit.md`と同ディレクトリの3CSVを参照。現行BADGESは称号と実績の共有定義92件、独立レート称号5件を足して97件、きせかえ37件。新しい報酬はデイリーで許可済みの4称号以外追加しない。塔5項目の実績状態はhidden、他87件active、retired0。取得判定・BADGES全取得数を使う着せかえ・装備中二つ名は変更しない。

所有者の確認回答により、塔5項目を共有の称号・実績一覧・通常プロフィール・達成率からも一時非表示にする。既存の一覧を再利用しactive87件のみ表示、先生は全92件を確認可能。装備中の塔の二つ名と履歴・着せかえ条件は保持。先生用ダッシュボードはteachers/<account>を確認してから全件条件を表示し、非先生には画面を描画しない。

`node scripts/audit-rewards.cjs`で現行の定義・判定式と行番号を再生成。取得経路のモード差・旧塔の未確認・説明不一致は報告書に明示。CSVのID、件数、BOM、状態フィルターと先生用/通常用表示を`npm run test:rewards-audit`で検証。アカウントや取得履歴の一括変更はない。

Pagesの公開後、deployジョブでgame-version.jsを実HTTP取得し、検証済みバージョンとの一致を確認する。ブラウザ用Firebaseモックは親子パスのトランザクションを直列化し、実SDKでは発生しないモックの上書き競合を防止。新B2では実タッチで15問連続正解し、確定得点と試合期限の結果まで検証する。
