# オンライン難易度別制度：実装と本番切替記録

2026-10-13。基準main：`9fa9ac3115f280e82d1ffd00e361c914b188e957`。設計元：`f1d85fd`。作業ブランチ：`feat/online-rated-v2`。ユーザー承認済みの正式仕様で実装した候補。**本番未適用。** 最新ルール、実データ棚卸し、外部バックアップ、料金プランを確認するまで切り替えない。

## 正式仕様と保存構造

- 旧 `games/factor/accounts/$key/stats.rating` の移行時最新値をEASYにそのまま引き継ぐ。NORMALは1500。旧値が欠損の場合のみ1500。不正な型は移行停止。
- EASY/NORMALそれぞれ有効対戦数0から開始し、3戦以上で各ランキングへ掲載。自己レートは未掲載でも表示。旧総合ランキングと旧成績は残す。
- 新制度は `games/factor/onlineRatedV2`。`privateState` にプレイヤー・待機・進行中試合・確定台帳をまとめ、サーバーのtransactionで両者を同時に更新。
- `matchArchive/$id` は完了試合の原本・確定結果。原本の保存成功と一致を確認してから作業領域から移す。完了結果の再送・再ログインは参加者にだけ返す。原本は削除しない。
- 移行元全体のバックアップと `legacyArchive` を作業領域から分離。旧 `accounts` は書き換えない。未検証の既存アカウントを自動再移行しない。
- 移行マーカーと既存playerの存在で再初期化を防ぐ。以後新規アカウントは1500/1500。ただし移行に含まれていない既存アカウントは停止して調査する。
- 旧EloのK32、最初10戦の負の変動半減、JST月初ソフトリセットを難易度ごとに維持。A/Bは各難易度で共通。旧勝敗は引き継ぎ用バックアップに保存し、新制度の3戦条件へ加算しない。
- 追加称号はEASY/NORMALの達人1730、マスター1820、双璧のマスターは両方1820。最高到達値で永続保持。移行したEASYが閾値を満たす場合も判定する。既存称号の条件・装備・記録は変更しない。

## クライアントとサーバー

`src/online-rated-ui.jsx` は既存オンライン入口から呼び出す独立画面。`config.enabled` がtrueの場合だけ新制度へ進み、それ以外は旧機能を使用する。部屋番号対戦・CPU・大会・レイドは従来のコードを保持。

EASY/NORMAL選択→難易度別待機→A/Bだけ投票→固定難易度で開始。プロトコル2をサーバーで必須とし、旧 `qm/rooms` とは別に待機する。キャンセルは本人の待機ticketに限定。投票期限・同票はサーバーで決定。開始前の退出は無効、開始後の退出・切断は既存の8秒基準で判定。回答連番・現在の問題IDを確認し、再送は二重判定しない。別プレイヤーの正解で問題が進んだ場合は最新状態を取り直す。

Cloud Functions第2世代HTTPS/Node22、asia-southeast1候補。IDトークンの検証と `logins/$accountKey/$uid` の存在確認を毎回行う。ブラウザへ秘密鍵・管理者SDK・問題seedは渡さない。画面は既存BattleBoard/TargetCardと共通ミュートを使用。送信先は指定プロジェクトの正規HTTPSエンドポイントに限定。

サーバーは既存 `index.html` の問題生成・多項式判定・Aの得点・BエンジンをASTから抽出して再利用する。クライアントの勝者・HP・レート申告を採用せず、実際に選んだ2枚をサーバーが判定し、サーバー時計で進行・攻撃・勝敗を確定する。レートは確定台帳に基づき両者同時に更新する。

**負荷・費用の未確認点：** 現候補は1秒ごとの状態要求と共有作業領域のtransactionを用いる。プレイヤー人数・同時対戦数・通信量・遅延を本番規模で検証する必要がある。エミュレータでの成功だけで全国・学校同時利用の容量や費用を保証しない。Functions導入にはBlaze等の課金条件の確認が必要。プラン変更・有料サービス追加はまだ実施していない。

## ルール差分候補

`scripts/prepare-rated-rules.cjs` はConsoleの最新全文から候補ファイルを作るだけで、デプロイしない。

1. `onlineRatedV2` をserver-onlyとして追加。公開configのみ認証済み読取可、全クライアント書込不可。
2. `qm/slot/.write` に切替中の新規受付停止条件を追加。待機を作った本人による削除は維持。
3. `rooms/$code/meta/.write` に `qm:true` の新規部屋停止条件を追加。
4. `rooms/$code/players/$uid/.write` に旧ランダム部屋への新規参加停止条件を追加。既存参加者の更新・部屋番号対戦は維持。

他の枝・検証条件を保持。上位root/games/factorに包括的な許可があれば候補生成を止める。**既存players親のhost許可は子の禁止で取り消せない。** その権限を今回勝手に変更しないため、悪意ある旧hostへの完全な停止保証ではない。新制度は別領域で守り、旧ratingへの本人書込みという従来の弱点は旧記録側に残る。移行値取得時の停止・監査・差分照合が必要。

ローカル検証には以前受領したConsole書き出しを使用した。この過去ファイルを現在配信中のルールと断定しない。今回ユーザーは最新全文とSpark/Blaze名を共有する方法を選択済みだが、まだ実物を受領していない。

## 復旧

- 新規受付を停止し、進行中の新制度試合を終了・確定させる。確定結果と移行原本を再取得して保全。
- `config.enabled:false` と `privateState.enabled:false` に戻す。旧受付を再開する場合は `stopLegacyQuickMatch:false`。旧accounts・旧成績は未変更なので復元インポート不要。
- 新制度のEASY/NORMAL、称号、確定試合・archiveを削除しない。再開時は既存新制度データを使い、移行ツールで初期値を再投入しない。
- Pagesは既存workflow_dispatchの検証済みmainコミットへのロールバックを使用。新制度後のレートを旧statsへ自動逆移行しない。逆移行を要する場合は別監査と承認が必要。
