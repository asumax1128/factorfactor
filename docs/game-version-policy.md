# 正式バージョン管理

正式値は `version.json` の整数major/minor。`game-version.js` はビルド生成物で画面に `Ver. X.Y` を表示し、配信の `release-manifest.json` に同じ値を記録する。

2026-10-13、所有者の確認で画面のver.5.9を起点とし、今回をVer.5.10とする。コードコメントのver.8.4等は歴史的な実装ラベルで、正式リリース値ではない。

- 公開ゲームのバグ・UI・画像・演出・機能・バランス・称号変更は、公開1回につきminorを1増やす。5.9→5.10→5.11。浮動小数で管理しない。
- 調査のみ・未公開試作・資料だけでは本番バージョンを更新しない。作業ブランチの値は公開予定値で、公開成功まで正式稼働版は変わらない。
- major変更は所有者の事前確認が必要。CIもAPPROVED_MAJOR_VERSION未設定の整数変更を拒否する。この変数の設定は承認後に所有者が行い、通常更新では不要。
- CHANGELOG.mdへ内容・検証を追記し、生成物をコミットする。画面とコード・配信manifestの不一致は許さない。
- CIはpush前のmainと比較し、ゲーム内容変更時のminor未更新を拒否する。検証済みコミットへのロールバックは当時のバージョンを維持し、この増分チェックを適用しない。
- Claude引き継ぎ時もこの方針を維持。Firebase移行やルール変更は別途差分・承認を扱い、バージョン更新を承認の代わりにしない。
